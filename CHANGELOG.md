- **A command-line entry point for `tools/harness-matrix/scrub-paths.mjs`.** The module that decides whether a laptop's directory layout reaches a public git history had no way to be run: every function in it was written for one caller — the extractor that produced this repository — and that caller was a scratch script that did not survive the extraction. What shipped was a library whose only user was its own test file, so the next person preparing an extraction would either re-write that script (a second, drifting copy of the longest-prefix-first ordering this module exists to own) or skip the sanitise step entirely, which fails with no error message. Two modes: `--src <dir> --dest <dir>` writes a scrubbed copy and then asserts over the copy — the proof is not optional and there is no flag to skip it — and `--check <dir>` asserts over a tree somebody else produced, which is the mode a release checklist runs. `--files-from -` reads the file list from stdin, so `git ls-files | … --files-from -` keeps `.gitignore` the single definition of what is publishable rather than duplicating its un-ignore ladder in a second place. Exit codes match `run-harness.mjs` so the two compose in one shell chain (`0` clean, `1` a host path survived or a substitution moved a lint verdict, `2` bad invocation, nothing written); `--dest` inside `--src` is refused before the first write, because recorded runs are immutable evidence. Covered by four new cases in `scrub-paths.test.mjs` that run the CLI as a real process — exit codes and the direct-execution guard are precisely what an in-process call would not exercise.
- **A fifth policy, `policies/opus48-plus-lite.yaml`** — the tokenomics cell, and the one that tells the Gemini Enterprise story in a single file: judgment stages (requirements, design, plan-packets, review, judge) run `composition: solo` on Claude Opus 4.8 and make **no SDK call at all**, while production stages (execute, and the repair rounds verify carries with it) run `composition: delegated` to a `gemini-3.5-flash-lite` worker. Its tier boundary is the driver/worker line, which is what a cost-conscious team would actually deploy; the older `gemini35-plus-25-flash-high` cuts the same split with both tiers as *workers*, which is the cleaner experiment. Neither supersedes the other and both ship. It is also the first policy to hold **both** composition kinds in one `models[]` list, sharing one driver leaf — legal because the runtime decides delegation per *stage*, not per run. On the SWE-bench Pro leg it names all three phases explicitly and delegates every one, so it resolves to exactly the same cell as `all-gemini-flash-high` there; the two differ only on SDLC stages.
- **`tools/docs-links.test.mjs`** — every relative Markdown link in every tracked (and every new-but-not-yet-committed) `.md` file must resolve to a file that exists, and no `.md` file may link into the gitignored `runs/` evidence tree. Offline and free. This is the durable half of the documentation fix below: the reshape broke fourteen links without touching a single file that contained one, because nothing in a build, a typecheck, or the rest of the suite reads prose.

### Fixed

- **The scoreboard's "Claude edits" row accused the tokenomics cell of the exact violation the run existed to disprove.** On the first live SDLC pass of `opus48-plus-lite` — RESOLVED, 14/14 tests, judge 9/10, zero audit flags — the closing scoreboard printed `Claude edits 5 — NON-ZERO: the harness wrote code, investigate audit.json`. The counter behind it (`editCount` in `audit.mjs`) counted every Edit/Write/MultiEdit tool call wherever it landed, and the wording was authored when every shipped policy delegated every stage, where any driver edit *is* a violation. `opus48-plus-lite` is the first policy with `solo` stages, and a solo stage's job includes writing its own contract file into the run's `out/` directory — outside the working tree, never shipped, exactly what the integrity claim ("the driver writes no shipped code") is **not** about. All five counted edits were `out/` contract writes; zero reached `workdir/`. Fixed by asking the question the row always meant: `audit.mjs` now classifies each edit by **destination** (`editTargetsTree`, mirroring the split `bashEditsTree` already made for the Bash write channel — one rule, both channels) and records `treeEditCount` beside the existing total, and a single `claudeEditsRow()` in `logfmt.mjs` replaces the two byte-identical inline ternaries in `logrender.mjs` plus the third hand-rolled copy of the same accusation in `tools/report.mjs`, so the SDLC scoreboard, the Pro scoreboard and the cross-run report cannot drift apart again. The row is null-honest across all its states: a measured zero says the claim holds and names the `out/` writes for what they are; a non-zero stays loud; an `audit.json` recorded **before** this split says the tree count is NOT established and points at the `$0` re-derivation (`auditRun` re-reads the trajectories already on disk — run directories are never rewritten in place); and a run with no `audit.json` at all, or an unauditable runtime with no trajectory, says so rather than grading a placeholder zero as a measurement. The footer descriptors in `kinds/sdlc.mjs`, `kinds/swepro.mjs` and `replay-log.mjs` carry the new fields through — the projection previously dropped everything but `editCount`, which would have silently forced the "NOT established" fallback on every fresh run. The first live tiered **Pro** run, hours later, sharpened the rule once more: its solo repro phase legitimately wrote the repro test into the working tree (computeDiff strips test/repro paths from the graded diff — that is the enforcement), and its two solo phases collected 28 false `driver-predelegation-inspection` flags that the scoreboard presented as "the delegate-first control refusing repo access" when nothing was refused — the delegated-cell checks were gated on the RUN-level delegation flag, not the phase's. So composition comes first, destination second: `auditRun` now resolves each phase's composition from `expectByPhase` (the same records the manifest is written from) and every delegated-cell check, including the edit split, keys off it. `treeEditCount` counts tree edits during **delegated** phases (the violation — impossible by construction, so any non-zero is also a tooling hole, and each is now recorded as a `driver-direct-edit` flag with its path); `soloEditCount` reports solo-phase writes as information. The repro phase's `test-edit-attempt` family is off by design (`skipChecksByPhase`, recorded in audit.json) — its contract IS a failing test. Re-derived at $0 over both live runs' trajectories: 0 tree edits during delegated phases on each, 5 and 3 solo writes, and P4b's false lock count drops from 28 to 0, leaving its one true flag (a delegation that ran thinking NONE against a HIGH pin during an environment-recovery retry). Seven tests in `logfmt.test.mjs` pin every branch, including both live-run shapes.
- **The `$0` preflight skipped every worker check on the tiered policy, so a missing venv or missing Vertex ADC was discovered after three paid stages instead of before any.** Both kinds passed `runtime.preflight()` the binding of their **first** stage, which is only the right binding if a policy delegates everywhere or nowhere. Four of the five shipped policies are uniform, so the shortcut held and nothing caught it. The fifth is `opus48-plus-lite`, the tokenomics cell: on SDLC it resolves requirements/design/plan-packets `solo` and only `execute` `delegated`, so stage 0 is a bare model string, `isDelegated` said false, and the three delegated-cell checks — worker venv present, `import google.antigravity`, Vertex ADC present — never ran. A laptop without ADC therefore passed a gate whose own comment promises *"all $0, before any build or spend"*, paid for three Opus stages, and died at `execute`; the zero-delegation gate then bought that same failure twice more under `max_attempts: 3`. The same expression fed the header's orientation paragraph, which read the driver off that string and announced **"Claude Code (undefined)"** above a table that named the driver correctly on every row. Both are one mistake — treating stage 0 as a proxy for the run — so both are fixed in one place: `preflightBinding()` in `kinds/lib.mjs` returns the first **delegated** stage's binding, falling back to the first stage when nothing delegates, and `kinds/sdlc.mjs` and `kinds/swepro.mjs` both use it for the preflight and the header. On a uniform policy it returns exactly what stage 0 returned, so no shipped run changes. Pro adopts it too even though its three phases currently delegate together — the v2 grammar has allowed a per-phase mix since it was written, and the next tiered Pro policy should not have to rediscover this. Covered by `kinds/preflight-binding.test.mjs` (5 tests, offline, `$0`): the helper's three cases, plus a regression that resolves the **shipped** `opus48-plus-lite` against stage ids derived from the **shipped** `sdlc-mini` template — the bug needs a real policy and a real stage list disagreeing about which stage delegates first, which no hand-written fixture would have reproduced — and a sweep asserting that for all five policies × both kinds, preflight goes delegated exactly when the run does. Mutation-checked: restoring the `stages[0]` expression fails 3 of the 5.
- **A policy's declared worker region never reached the worker.** Every `vertex` leaf carries a `region:`, the loader *requires* it, and `policy_snapshot.yaml` froze it into the evidence — but nothing on the executable path read it. `gemini_worker.py` took its location from the ambient `GOOGLE_CLOUD_LOCATION` alone, and, worse, wrote that same ambient constant into the `worker-usage-*.json` sidecar as `vertex_location`. So the receipt agreed with the environment no matter where the tokens were actually billed: a provenance artifact that could not contradict the environment, which is to say no evidence at all. It had been invisible because every policy happened to declare `asia-south1`, which was also the default. The Flash-Lite pin ended that — Vertex serves `gemini-3.5-flash-lite` on `global` **only**, returning `404 Publisher model … was not found` in both `asia-south1` and `us-central1` — so the next delegated run would have failed outright rather than merely mispriced. Fixed at all four layers: `gemini_worker.py` gains an optional `--region` that outranks the environment and records the location it *resolved*; `policy-core.mjs` carries the leaf's region into the delegated binding as `worker_region`; the per-run Skill renderer emits `--region "<value>"` on the worker command line; and the call site passes the binding's value through. Both `worker_*` keys are **omitted rather than nulled** when a policy does not declare them, so v1 policies — whose bindings carry no region at all, including the frozen snapshots inside evidence bundles already handed out — replay unchanged and get the worker's own default. Eight new tests across `guard.test.mjs`, `worker-env.test.mjs` and `kinds/lib.test.mjs` pin both ends of the chain: that a shipped policy's declared region survives `loadPolicy` → binding → argv, and that an *undeclared* region emits no flag. Mutation-checked — deleting the emission line fails two of them.
- **The driver pin on the three current cells was a generation behind the model they are meant to anchor.** `all-opus` and `all-gemini-flash-high` still ran `claude-opus-4-6` while `opus48-plus-lite` had already moved to `claude-opus-4-8`, so every delta measured between the delegated cell and the tokenomics cell carried a driver change on top of the tiering change it was supposed to isolate. All three now pin `claude-opus-4-8` at `--effort high`; the only thing separating them is what gets delegated. The two **historical** columns deliberately stay on `claude-opus-4-6`, which is the driver their recorded passes under `examples/*/passes/reference/` actually ran with — re-pinning a frozen column to a driver it never ran on would make the policy describe a run that did not happen. There is no pricing consequence either way: the driver's cost comes from Claude Code's own CLI-reported figure, never from a rate-table lookup, which is why composition members may omit `pricing:` entirely rather than carry an invented number to satisfy a validator. One existing test in `kinds/sdlc.test.mjs` compared the two columns as "identical but for the worker"; the driver divergence is now **asserted on both sides** before being normalised away, so a fourth difference still fails.

- **`opus48-plus-lite.yaml` described a division of labour on SWE-bench Pro that this repository's own guard forbids.** Its header read: on Pro, Opus 4.8 "reads the repo, localizes, decides what the patch must do, and verifies what came back". Three of those four clauses are false by construction. On a `delegated` cell the driver has no file-editing tool, cannot write into the working tree through Bash either, and — until its first delegation of a phase-attempt — cannot even Read/Grep/Glob the repo (the delegate-first lock in `runtimes.mjs`); the Skill it is given says in terms *"Hand the worker the PROBLEM, not the SOLUTION"* and forbids a re-delegation from carrying the remedy; and `localize`'s delegated work is labelled *"analysing where the bug lives (the localization)"* in `kinds/swepro.mjs`, which is to say the worker does exactly the thing the header credited to the driver. What the driver actually does on Pro is compose the task, write the phase contract files outside the repo, and verify what came back — `git diff`, tests through `run-in-env.sh`, reading the files the worker names. That is still the judgment half, and the policy still satisfies the tiering it was commissioned for; the header now says so accurately, and the routing rule's `reason` with it. This mattered enough to fix before publication because the claim was checkable **and wrong in the flattering direction**: the guard that falsifies it is in the same repository, so a reader who checked would find the harness contradicting its own policy file about who did the engineering — the one thing this deliverable exists to be trusted on. Prose in one policy file; routing, bindings and every recorded run are unchanged.
- **`sdk-probe/probe_offline.py` reported three things that were not true**, all of them in the probe rather than in the SDK — which is worse than a silent script, because the output reads as findings. Against the pinned `google-antigravity` 0.1.7: (a) it called `len()` on `policy.allow_all()`, which returns a single `Policy` and not a sequence, and printed the resulting `TypeError` as `allow_all() -> FAILED` — a helper the shipped worker uses on every delegated run; (b) it printed a hardcoded `capabilities.command_execution`, a field 0.1.7 does not have, so the `AttributeError` was caught by the enclosing handler and reported as `construction -> FAILED` on the line directly below `construction -> OK`; (c) it counted `MODEL_CLAUDE` by matching *lines*, but a Go binary's string table is one concatenated blob, so it reported "24 matches" whose first three entries were shell-error and DevTools strings and whose truncated tail never showed the Claude 4 names. Each now asks the object what it is rather than assuming: shape-agnostic printing for the policy helpers, capability fields read off the model, and a bounded regex that extracts the enum names and prints a completeness check (`29 distinct, 37 matched of 37 prefix occurrences`) so a future name outside that shape shows up as a miss instead of vanishing. The probe also now prints the expanded policy list, which is where the `workspace_only` floor documented in [docs/antigravity-sdk.md](docs/antigravity-sdk.md) became visible.

### Removed

- **`templates/policies/` and the one file in it (`opus-plus-flash.yaml`, 223 lines).** A cost-optimised routing policy belonging to the SDLC orchestrator this harness was built alongside, carried in by the extraction. Nothing in this repository loads it: the harness reads only the file named by `--policy`, and `--policy` resolves against `tools/harness-matrix/policies/`. Its loader lives in the other repository and did not come across. It therefore shipped as a policy a reader could reasonably believe was selectable, and was not. `templates/` now contains exactly what the SDLC kind reads at run time: `sdlc-mini/template.yaml`. Nothing is lost with it — the per-stage tier split it encoded is reproduced, stage by stage with its original reasons, in the header of `tools/harness-matrix/policies/gemini35-plus-25-flash-high.yaml`.
- **`tools/harness-matrix/agy-trajectory.mjs` (346 lines).** A post-run decoder for the local SQLite conversation store written by the Antigravity CLI (`agy`). Nothing imports it and no test covers it; the CLI runtime whose evidence it read was removed on 2026-07-23, and the SDK worker reports its own usage natively, so no code path in this repository produces a store for it to decode. It was kept "for a possible revival", which in a published tree reads as a component of the system rather than as an orphan. Recoverable from git history if the CLI ever returns.
- **`tools/lib/benchmark-brief.mjs` and its test (the whole `tools/lib/` directory).** A brief template parameterised over `{SWE-bench Verified, SWE-bench Pro} × {orchestrator, harness}`, which existed because in the repository this was extracted from two applications described the same benchmark in two voices from two files. Only one of those callers came across, and three of the four combinations are unreachable here: there is no SWE-bench Verified corpus (the fetcher and the Pro kind are Pro-only) and no orchestrator track. The abstraction that existed to hold two callers in step held one, and its own docblock explained itself by naming `run-swe-pro.mjs`, a file that is not in this tree. The template is now `proBenchmarkBrief()` inside `tools/harness-matrix/export-dashboard.mjs`, beside `delegatedSdlcBrief()` — the other brief that exporter writes — and produces byte-identical output but for one phrase (see *Changed*). Its two properties worth keeping are now tested against the `brief.md` the exporter actually writes rather than against a helper's return value: the delegated and single-seat shapes walk one identical section outline, and no brief carries an instance id, count, seed, date or dollar.
- **The `security_review` rule in `tools/harness-matrix/policies/gemini35-plus-25-flash-high.yaml`.** The rule routed a stage named `security_review` to the premium tier. `templates/sdlc-mini/template.yaml` defines no such stage, and a rule whose `when.phase` names a stage no template emits is neither an error nor a warning — it simply never matches. It read as a stated tier decision while doing nothing, which is the one thing a policy file must not do. Routing is unchanged for every real stage: the `default` rule already sends anything unrecognised to the premium tier, which is the tier that rule asked for. The file's header records why it is absent rather than leaving the next reader to rediscover the trap.

### Unchanged

- **What a run does is byte-identical to the pre-reshape version.** The stage sequence, the gates, the retries, the enforcement predicate shared by tool removal + pre-execution hook + post-run audit, and the artifacts written are untouched (`kinds/`, `audit.mjs`, and the body of `runtimes.mjs`). New runs still write to `tools/harness-matrix/runs/<taskId>/<runtime>--<policy>/<stamp>/`. The three files that did change, changed only in what happens before a run begins: `run-harness.mjs` gained the selector check above, `gemini_worker.py` gained the configuration preamble, and one `runtimes.mjs` preflight error stopped naming a specific Google Cloud project in its fix hint (both per the `GOOGLE_CLOUD_PROJECT` entry). The call shape, the policy grant, and the sidecar contract are as they were.
- **Model routing in the four policies that existed at the time (`all-opus`, `all-gemini-flash-high`, `all-gemini-25-flash-high`, `gemini35-plus-25-flash-high`) is unchanged.** (A fifth, `opus48-plus-lite`, was added later in this same unreleased block — see Added.) Three changed only in comments. The fourth lost the `security_review` rule described above, which could not match any stage the templates emit and so routed nothing. Every cell id, model pin, adapter, API, region, thinking level, retry policy and limit is as it was, so a run under these files resolves exactly as it did before.
- The offline suite still passes with no credentials of any kind.
